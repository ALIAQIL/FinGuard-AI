# Real-data benchmark

This report is generated by `python -m finguard.benchmark` against the public anonymized ULB/Worldline dataset. The raw CSV is not committed.

## Run configuration

- Dataset: 284,807 rows, 492 original fraud labels.
- Cleaning: no contract-invalid rows; 1,081 exact duplicate rows removed before splitting.
- Modeling rows: 283,726; fraud rows after deduplication: 473.
- Split: chronological 60% train / 20% validation / 20% test.
- Features: `Time`, `V1`–`V28`, `Amount`, hour/day derived from `Time`, and `log1p(Amount)`.
- Logistic regression: standardization plus balanced class weights.
- XGBoost baseline: CPU `hist`, 120 trees, depth 4, learning rate 0.08, two threads, training class weight from the train split.
- Tuning: `TimeSeriesSplit(n_splits=3)`, four randomized trials, and a four-combination grid search on the training partition only.
- Search metric: average precision (PR-AUC), selected before validation/test evaluation.
- Operating policy: rank transactions and send the top 1% to investigation; F1 threshold results are retained as a secondary diagnostic.

## Measured result

| Model | Test PR-AUC | Precision@1% alerts | Fraud capture@1% | F1 at 1% alerts |
| --- | ---: | ---: | ---: | ---: |
| Logistic regression | 0.7611 | 0.1127 | 0.8649 | 0.1850 |
| XGBoost baseline | 0.7820 | 0.1127 | 0.8649 | 0.2148 |
| XGBoost randomized search | **0.7888** | **0.1127** | **0.8649** | 0.1928 |
| XGBoost grid search | 0.7649 | 0.1109 | 0.8514 | **0.2062** |

The randomized search was selected because its training-only temporal CV PR-AUC was 0.7900, compared with 0.7766 for the grid search. Its held-out test PR-AUC was 0.7888 versus 0.7820 for the baseline. Under the fixed 1% alert budget, both the baseline and selected model captured 86.49% of test fraud, with 11.27% precision among investigations. This is one offline run, not a production fraud-reduction or latency guarantee.

The measured output is also written to `reports/benchmark_ulb.json`. Re-run the command after changing hardware, dependency versions, or configuration; model results should not be treated as universal.

## Important limitations

- The dataset covers only two days and contains anonymized PCA components.
- It has no stable customer/card identifier, so no customer-history feature is claimed.
- The exact duplicate policy changes the number of fraud examples; the choice is documented and should be sensitivity-tested.
- The dataset is public and anonymized, but it is not representative of every issuer, geography, product, or current fraud pattern.
- The benchmark measures offline batch scoring, not Kafka-to-alert end-to-end latency.
- The selected model is not serialized or loaded by the streaming job; streaming `risk_score` remains intentionally unpopulated.
- Runtime and dependency versions are recorded in `reports/benchmark_ulb.json` because metric and threshold variance can occur across environments.
- The exact duplicate policy is explicit, but a future sensitivity experiment should compare it with a keep-duplicates policy.
