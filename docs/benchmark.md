# Real-data benchmark

This report is generated by `python -m finguard.benchmark` against the public anonymized ULB/Worldline dataset. The raw CSV is not committed.

## Run configuration

- Dataset: 284,807 rows, 492 original fraud labels.
- Cleaning: no invalid or missing rows; 1,081 exact duplicate rows removed before splitting.
- Modeling rows: 283,726; fraud rows after deduplication: 473.
- Split: chronological 60% train / 20% validation / 20% test.
- Features: `Time`, `V1`–`V28`, `Amount`, hour/day derived from `Time`, and `log1p(Amount)`.
- Logistic regression: standardization plus balanced class weights.
- XGBoost: CPU `hist`, 120 trees, depth 4, learning rate 0.08, two threads, training class weight from the train split.
- Threshold: selected on validation F1 only; the test set is not used to select it.

## Measured result on this machine

| Model | Test PR-AUC | Test ROC-AUC | Precision | Recall | F1 | Precision@K | Train time | Test scoring |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Logistic regression | 0.7611 | 0.9841 | 0.5268 | 0.7973 | 0.6344 | 0.7297 | 2.06 s | 0.016 s |
| XGBoost | **0.7820** | 0.9804 | **0.8667** | 0.7027 | **0.7761** | **0.7568** | 2.84 s | 0.069 s |

The XGBoost result is better on PR-AUC, precision, F1, and precision at K for this run, while the logistic baseline has higher recall. XGBoost scored 56,746 test rows in 0.069 seconds on this machine, approximately 0.0012 ms per row in this in-process batch measurement. This is not a production serving-latency guarantee.

The measured output is also written to `reports/benchmark_ulb.json`. Re-run the command after changing hardware, dependency versions, or configuration; model results should not be treated as universal.

## Important limitations

- The dataset covers only two days and contains anonymized PCA components.
- It has no stable customer/card identifier, so no customer-history feature is claimed.
- The exact duplicate policy changes the number of fraud examples; the choice is documented and should be sensitivity-tested.
- The dataset is public and anonymized, but it is not representative of every issuer, geography, product, or current fraud pattern.
- The benchmark measures offline batch scoring, not Kafka-to-alert end-to-end latency.
